## Programmable Watchtower / ASP Challenge Walkthrough

The happy-path receipt says an opaque Lightning payment can release an Ark-backed ASP settlement. The challenged branch asks whether that same receipt set proves the ASP actually delivered the signed inbound-liquidity minimum.

- Contested violation: `deliveredInboundMet`
- ASP counterclaim: `deliveredInboundSats >= promisedInboundSats; settle and release ASP fee`
- Challenger claim: `deliveredInboundSats < promisedInboundSats; slash or force exit`
- Happy path check: `75000 75000 OP_GREATERTHANOREQUAL` -> `true`
- Disputed branch check: `10000 75000 OP_GREATERTHANOREQUAL` -> `false`

| receipt stage | receipt id | what it proves |
| --- | --- | --- |
| `payment-condition-receipt` | `ebb9fc532cd6e5417f272c3e720ba75d94eec9c7864afa8796da170f2e214395` | Payment hash, amount, invoice hash, and preimage-witness commitment are bound without exposing the route. |
| `watchtower-utxoref-receipt` | `9e8cf05d6d7d58b10265ff065de8b1339415c7cfaf482e597cfe3e657e4e1f39` | The watched UTXORef transition is tied to the payment-conditioned program state. |
| `asp-settlement-receipt` | `9b8f3a7342bf1815c2951aa62b6dc5b03f006160db2c7c8a29d6ca8ddede6eec` | The ASP has a normal settlement path if delivery, fee, CLTV, and exit checks all pass. |
| `asp-forfeit-receipt` | `45cf25cad368ae31ce24a9368723a790509b416f0aebe195d8be7afff0477817` | A slash or force-exit path exists if the ASP cannot satisfy the opened verifier step. |
| `watchtower-challenge-id` | `d9961287679a890db8fdac7340b7350c1886f4fdbbc1f8b90c610863c1deb701` | Mismatched payment-conditioned UTXORef transitions become challengeable evidence. |
| `asp-challenge-id` | `0ffbf2d26384c99eecee140e1729de4d312dd10b8237a04ea8566f6fdc3c66dc` | Failed ASP policy checks become slashable or force-exit evidence. |

Verifier-trace model:

- Commit the ZK verifier program id and public inputs: payment proof id, Ark receipt ids, promised sats, delivered sats, fee ceiling, CLTV ceiling.
- If the ASP disputes the result, bisect the committed verifier trace until one step is opened.
- The opened step is the delivery comparator, not the Lightning route: deliveredInboundSats >= promisedInboundSats.
- If that step evaluates false, the challenge path authorizes slash or force-exit handling.

Caveat: Bitcoin Script does not natively verify a full modern ZK proof here. The BitVM shape is an optimistic verifier-trace dispute: receipts commit to the proof result, and fraud opens the contested verifier step.
